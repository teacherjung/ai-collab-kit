# 清環境的考題只看幾個名字，退化成列名照樣全綠

- 日期：2026-08-10
- 本文條號：E4、E8
- 發生什麼：同一個盲點出了三次：考題要證明「叫版本控制工具前，它那一族環境變數整族清掉了」，看的卻只是幾個名字。第一次（8/10）：推送前鉤子與體檢程式宣稱整族清光，其實照名單只清七個；考題也只注入那七個、斷言它們消失，等於拿實作自己的名單驗實作。複審者實跑鉤子、注入名單外的名字，五個子行程都看得到，鉤子照樣放行。修法改成按字首整族清，考題改注沒列過的名字。第二次（8/15）：一支變更把清法收成共用程式，各呼叫點改用它；呼叫點的考題只注入事故那一個變數（指定倉庫在哪的那個），看答案還對。實作者自己的突變在呼叫點只打「把清環境那行拿掉」，「退化成列名」那一刀只打在兩份殼層清法上。照實作者的轉述，複審者第一輪把呼叫點換成「只刪那一個變數」的列名版，全部照樣綠，而這支變更存在的理由正是列名補不完。實作者先試再挑一個變數一起注入，量了四種呼叫形狀：除了事故那一個，另外試的三種注入沒有一種對四種都有影響，挑變數本身又是一次列舉；第一版探針還量錯過（殼層沒照預期分詞，錯誤輸出被讀成「行為改變了」）。最後保留只看答案的題，每個呼叫點另補一題：在執行路徑最前面放一支假的工具程式，記下它實際收到的那一族變數，斷言一個都沒有，也斷言它真的被叫到；注入的名單刻意放一個編出來、沒人列過的名字。第三次（9/18）：這批工具搬進共用套件，原本那批直接看子行程整族的題隨舊閘一起刪掉，那支變更把這份職責寫成由套件那幾題接手。那句寫在一份考題檔頭；同一份檔頭往下幾行，早就記著第二次的教訓：每個呼叫點要兩種題，只有看答案那種，清法退化成列名照樣全綠。套件那幾題也直接看子行程，四題的題名都講那一族，斷言卻都只看那一個名字（其中兩題的題名後半就寫明只看它）。掃描者點出這件事。實作者補了一題看整族的，另配一個不清環境的對照組，證明探針看得到。複審者在自己的審查樹裡把執行器改成只刪那一個變數：新題紅，套件那支考題檔照樣全綠。
- 代價：第一次：第一輪退回（同輪共五條，這是其中一條）；鉤子在真環境有沒有因此出事，沒查。第二次：第一輪退回（同輪另有一條：平台的命令列工具會自己再叫版本控制工具，四處都漏清）；第二輪又因第一版錯探針留下的失實句退回（那句寫在六處註解，複審者點名一處，其餘是實作者自掃找到）；這兩輪的經過只見於實作者的轉述。第三次：掃描後補題，多一輪複審（同一輪也收了掃描的其他幾條）；套件那幾處的補題進了待辦，2026-10-06 讀套件主幹，那四處呼叫點的考題仍只看那一個名字。
- 教訓：要證明「整族清掉了」，考題直接看子行程實際收到什麼，斷言那一族一個都不剩；注入的名單放一個沒人列過的名字，再配一個不清環境的對照組，證明探針看得到。拿實作自己的名單驗、只看答案還對、只看一個名字，三種都是列舉，只是間接證據，擋不住清法退化成列名。突變除了「整個拿掉」，也要打「退化成看起來還在清」那一刀。搬家刪舊題時，對一下接手的題是不是一樣強。
