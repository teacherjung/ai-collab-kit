# 探針備份被掃進提交上了變更

- 日期：2026-09-09
- 本文條號：戊9、丁2
- 發生什麼：實作者寫探針驗證一道檢查的洞，順手把兩份工作流設定的備份寫在正在用的工作樹裡，接著整樹加入提交，一百三十八行無用副本跟著上了變更。獨立審查者第一輪就點名「實際差異多了兩份備份檔、與送審範圍不符」；而那兩份是會漂的版控副本，將來會變成說謊的來源。
- 代價：一輪審查白燒；記憶裡早有近親事故（叫子代理在自己正在用的樹上突變、被提交進去），這次是自己犯同一件事。
- 教訓：探針、突變、備份一律寫到工作樹外，最好整個實驗在另抽出的副本裡做；整樹加入提交前先看一次狀態清單，提交後再對一次檔案清單與變更說明是否一致。
