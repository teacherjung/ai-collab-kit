# 送審前預審抓到功能整個是死的

- 日期：2026-08-14
- 本文條號：戊9、甲3
- 發生什麼：實作者第一次在送獨立審查前，用四個互不重疊的視角各審一遍自己的變更，每條發現再派專門反駁它的視角去打；二十條發現有十三條被打掉（含兩條被誇大成阻擋級的既有問題），留下七條，其中一條是那支變更最壞的結果本身：一個開關根本存不起來。實作者自己跑一行才確認那條是真的；第一版彙整程式還把存活的發現全過濾掉、印出「0 條」。
- 代價：差一步就把「開關存不起來」送進正式審查；預審一次省下好幾輪返工。
- 教訓：正式審查每輪很貴，送審前先多視角預審加逐條反駁，反駁者不確定就判不成立、預審者一律唯讀；預審抓到的每一條要自己再驗才動手，連彙整程式也要驗。
- 來源：2026-08-14（無變更編號；首次預審的那支變更）
