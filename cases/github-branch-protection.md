# 逃生門開著＝每次操作都在繞過

- 日期：2026-08-02
- 本文條號：甲2
- 發生什麼：為了讓協作規矩有平台強制力，專案升級方案、給主幹開了分支保護；實作者第一版建議把「管理者也受限」關著留逃生門，實測當場打臉：用管理者身分直接推主幹成功，兩顆空提交進了主幹歷史。原因是人與兩個 AI 共用同一個管理者身分，逃生門一開等於每天每一次 AI 操作都在繞過。改成全開後實測三項（直接推、改寫歷史、合併紅燈的變更）都被擋住，設定與驗證紀錄同日進版控。
- 代價：兩顆繞過保護的空提交留在主幹歷史；若沒實測，整套升級等於白做。
- 教訓：單一身分下逃生門與強制力是同一個開關，逃生要改成刻意、看得見的動作；設定顯示啟用不等於擋得住，改保護設定後要重跑那三項實測。
