# 堆疊變更合進中間分支

- 日期：2026-07-28
- 本文條號：辛2
- 發生什麼：07-10 合併堆疊變更時用了刪分支選項，基底分支一刪、上層變更被平台直接關閉；規則當天寫進規則書，但執行合併的人讀的是另一份檔案、那裡寫著無條件刪分支。07-28 三支堆疊各自合進自己的基底而非主幹——畫面顯示已合併、檢查全綠、零錯誤訊息，主幹只拿到最底層那支，靠另開一支挑揀救回。07-30 補上機械閘：底不是主幹擋、有變更疊在上面擋、查不清楚一律當堆疊。
- 代價：兩次事故；第二次要另開一支把中間兩支的內容挑揀回主幹。
- 教訓：堆疊只能由下而上、每合一支就把下一支改底到主幹重審；「已合併＋全綠」不代表進了主幹。
