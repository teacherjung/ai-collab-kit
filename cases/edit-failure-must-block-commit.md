# 編輯沒寫入、提交照跑

- 日期：2026-09-03
- 本文條號：戊9、戊5
- 發生什麼：實作者用一支多處替換的腳本改程式，其中一處斷言錯、整支腳本一個字都沒寫入，但同一條指令鏈照樣跑了測試、提交、推送並發射審查。提交訊息與變更說明宣稱了程式裡根本沒有的改動，獨立審查者開審的是不實版本。之後同一坑換了四種長相再踩：行尾接註解吞掉同行後面的程式（本機聚焦考題沒抓到、推送前守門整卷才紅）；改變更說明的斷言失敗、鏈沒停，舊內文配新標題照樣上傳，審查者三十秒內讀走舊說明；考題檔本身語法錯，用「日誌裡沒有失敗記號」當閘被判成綠，審查者拿到連風格檢查都紅的版本；寫提示詞檔的步驟被同一串指令裡的管線吃掉、檔案零位元組，審查器只回「請告訴我要處理什麼」。
- 代價：主事故一輪審查白燒、停審補一顆坦白提交重發；四次再踩各付一次代價：一次守門整卷紅重推、一次殺掉審查重發、一次審查者審到壞版本、一次整輪空跑。
- 教訓：產生檔案的動作自己一個呼叫、寫完先驗大小或關鍵字再做下一步；編輯與提交分開呼叫、提交前看差異；閘只認退出碼，不用「日誌裡有沒有某字樣」代替；編輯失敗就整條鏈停下，不靠殼層的自動停止。
