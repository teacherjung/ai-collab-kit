# 共享狀態讓合併閘隨機紅

- 日期：2026-08-25
- 本文條號：辛1、辛4
- 發生什麼：跨變更試合併閘在獨立審查者手上退 1、在實作者手上連兩次退 0，看起來像兩支變更有真衝突。根因是一題考題在真正的家目錄數金絲雀目錄的個數，另一個工作階段同時在跑測試就會弄紅它，與被測程式無關；請對方暫停測試後，同一道閘首次重跑就綠。實作者另開一支修復，讓考題改在隔離根目錄裡看絕對值，並劃界說明同檔還有一條共用鎖沒修。
- 代價：合併閘隨機退 1，長得跟真衝突一樣、會誘使人去改根本沒問題的差異；補一支修復變更走了七輪審查。
- 教訓：共享狀態造成的隨機紅長得跟真衝突一樣；閘紅了先問「紅的是哪一題」，隔離重跑加完整重跑都綠才算環境干擾，不可只憑「重跑就過」放行；在共享空間認身分要認內容不數個數。
