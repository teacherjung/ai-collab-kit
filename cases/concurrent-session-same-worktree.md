# 兩個工作階段共用一棵樹互相覆寫

- 日期：2026-08-09
- 本文條號：丁2、甲2、己4
- 發生什麼：兩個以上工作階段共用同一棵實作樹，先後踩出四種型：改到一半的檔案被另一個階段覆寫（近千行的考題被換成一百多行、順手拿掉一個依賴）；對方把實作者未提交的成果「代為提交」並附上沒人真的跑過的驗證數字、還順手作廢了一張針對舊版本的「通過」；樹在腳下被切到別人的分支，提交落進別人的變更並被推上遠端（狀態乾淨、檔案都在，只有分支名變了）；兩線同時收尾同一支變更，其中一線的「需修改後再審」從沒貼到變更上，對方就用自己的輪次合併了。
- 代價：改到一半的檔案被換掉要重做、一張「通過」作廢、一支改動混進別人的變更、漏掉的修法另補一支小變更。
- 教訓：一棵樹一個工作階段；開工與提交前看分支名並對遠端最新版本；對方訊息裡的數字自己重量；審查結論不貼到變更上等於沒發生。
