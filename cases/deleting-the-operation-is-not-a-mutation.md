# 刪掉受測操作還綠，不代表考題假綠

- 日期：2026-07-29
- 本文條號：E8
- 發生什麼：一支讓雲端備份檔不帶完整帳號、匯入時再把原值保回來的變更，附了一題對照：匯出再匯入一趟之後，三個機密欄位還在（這三個欄位更早就不跟備份檔走了）。複審者把那一題自己的匯出、匯入兩行刪掉，結果照樣 21/21 全過，就判它假綠（實作者轉述；21 對得上那一版考題檔的題數，推論）。假綠＝考題亮綠燈，其實沒測到它說要測的東西。實作者反駁：這是保存型考題，守的是「操作做完、東西還在」，把操作刪掉，東西當然還在。他保留匯出匯入，只把匯入端保住機密的那一行改成一律清空，貼出的輸出是那一題連同另外兩題一起紅。同一則反駁裡他也承認那題太弱：它不種自己的值，只看前一題留下的機密「有值」。同一輪就改成先種一個本題專屬的新 token，解密後比對（另外兩個機密仍只看有值）。之後複審者做隔離突變複驗，撤回結論：基準 22/22，刪掉操作仍 22/22，改壞保存的那段就紅 3 題，這題在內（實作者轉述）。22 對得上加強後那一版的題數，所以複驗多半是在加強後的那一題上做的（推論）。兩邊把判準定成三條寫進專案的指示檔：修法生效型，拿掉修法要紅；保存型，保留操作、改壞保存的那段或強制給壞結果要紅，刪掉操作不算突變；兩型都要證明操作真的跑了，也不靠前一題留下的狀態。
- 代價：那一題沒有被刪，至今還在考題檔裡。它下一行的註解還寫著「這一題 v2 是假考題」，括號裡引的正是後來撤回的那個判準（刪掉兩行仍全過），理由寫的是只看前一題留下的狀態。這跟提交訊息寫的「撤回結論」對不上。分歧要等實作者貼出實測、複審者複驗之後才解開。定案之後，v4 到 v10 每一輪都又被抓到至少一個同一族的考題缺口（「同一族」是本案例的歸類，推論）：v4 好幾題共用前面一題建立的同一個帳戶（識別碼）；v5 一題「環境變數用完要還原」單題獨跑也綠，因為它根本沒動過環境變數（同一輪整題刪掉，斷言併進前一題）；v6 保存型考題只驗有值，這題也是（另外兩個機密換成錯的非空值，25/25 照綠）；v7 一題正式接線題實際匯入 0 筆，斷言只看不是 413（處理端改成回 500 照綠）；v8 一題不自己種值（單題獨跑會紅）；v9 跨租戶題靠前一題的資料；v10 四題沒證明匯入真的寫進去（存檔改成不寫入、匯入照回成功，四題單獨跑全綠）。那幾輪也有別的發現，不能算成因此多了幾輪。這支一路改到 v12 才合併。各輪的版本號與內容照合併提交訊息，是實作者的轉述。
- 教訓：突變前先分清考題是哪一型。修法生效型守的是「修法有沒有生效」，拿掉修法要紅。保存型守的是「操作做完、東西還在」，突變要保留那個操作，改壞保住東西的那一段，或強制給壞結果；刪掉操作還綠，不能據此判假綠。保存型的題先種一個只屬於本題的新值，讓操作有機會覆寫或清掉它；斷言比對那個確切的值，不是只看有值。不管是保存型還是修法生效型，都要另外證明受測操作真的跑了，也不靠前一題留下的狀態。
