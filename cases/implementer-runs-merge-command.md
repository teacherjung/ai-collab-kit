# 合併指令改由實作者自己跑

- 日期：2026-09-20
- 本文條號：A4、A2
- 發生什麼：舊 A4「合併鍵由審過這支的那一方按；實作者不按自己的」源自 7/30 的裁示。9/20 凌晨逐條走 A 節，裁示者先說按鍵的應該是審查者，實作者把它讀成要加一道機器比對（自報按鍵的人跟說明上的審查者不同就不放行）；裁示者回：「說真的，如果已經審核通過，誰按合併好像都沒有差吧。所以這條“不一樣就不放行”好像太嚴格也無意義。」實作者收回比對，並把 A4 當初的理由擺出來：7/30 時合併步驟裡「確認審查結論沒有阻擋」是人在判讀，實作者自己判讀就是利益衝突；這一步後來已由合併指令自動檢查結論、釘住版本，派另一方去按鍵，看的也只是同一套自動檢查。實作者給兩個選項，裁示者裁「b＝放寬」；b 的內容是實作者擬的：複審者通過、掃描與轉正式做完之後，由實作者自己跑合併指令，不經合併指令直接按平台的合併鍵不算。連帶 A3 拿掉「代合併」這個模式；A2 寫明「放行」是複審者的正式結論寫「通過」、按合併鍵只是執行，那句的字 9/21 由裁示者再改定。
- 代價：沒有事故；代價是舊規則下，在最常見的分工（一方實作、另一方複審）裡每一支都多一次交接：另開一個沒有記憶的工作階段、寫一份合併提示去按鍵，而那一方看的就是同一套自動檢查、沒有多看到什麼（實作者當時的分析）。
- 教訓：防利益衝突的規則要回頭查它當初防的那一步，現在是不是已經由機器做了；是的話就把「決定」（複審者寫「通過」）和「執行」（按合併鍵）分開，執行交給最順手的一方，但仍只准經過會自動檢查的那支指令。
