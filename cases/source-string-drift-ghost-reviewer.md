# 來源字串打法漂一次生出幽靈審查者

- 日期：2026-08-14
- 本文條號：F3、F5
- 發生什麼：同一個審查工具，實作者在不同輪次把來源欄打成兩種寫法（括號全形半形、有無前綴）；閘（＝合併前自動跑的檢查）的身分＝角色＋來源，同一位審查者被拆成兩個，其中一個身分的「需修改後再審」沒被自己撤銷，合併被擋；補撤銷後另一個身分又停在舊版本，再擋一次。修法＝用回那個來源字串對目前版本補發、不改舊留言；補發輪次要嚴格大於那個身分的最高輪次，而且別名在同一支變更內永遠存在、版本每動一次每個身分都要跟。
- 代價：合併被擋兩次，同一次審查要補發兩則結論。
- 教訓：每個審查工具固定一個來源字串、跨輪次一字不改，會變的東西（模型、力度、日期）不寫進來源；提示詞把它連同結論字串逐字給審查者。
