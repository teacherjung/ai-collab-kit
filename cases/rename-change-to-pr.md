# 規則裡的「變更」全書改叫 PR

- 日期：2026-09-24
- 本文條號：K2、J2
- 發生什麼：第二輪逐條微調走到 D3 時，裁示者問「一支變更」是什麼意思、是不是就是開一支 PR；實作者量到 58 條裡「變更」出現 9 次、套件沒有一處寫明它就是 PR，先建議本文照舊、另加一份用語對照，理由標成推論：規則刻意不寫 PR 是為了守進門五問的「通用」（換平台叫法就不同）。看到他自己改寫的 D3 直接寫了「草稿PR」，實作者改口建議全書改，理由是「白話」以他讀一遍就懂為準、而且範本也只有 GitHub 一種。裁示者 9/24 裁全書的「變更」都改成「PR」；同一天又問要不要改叫「合併請求」，原話「變更我覺得說的不清楚」，實作者以規則裡「合併」已經很多（合併鍵、合併指令、合併閘）、改了 AI 講話多半還是說 PR（推論）為由建議維持，他裁維持 PR、「草稿PR」也不改成「PR草稿」，對照表寫 PR＝合併請求。
- 代價：沒有事故；代價一是裁示者讀到規矩裡的「變更」得停下來問它指什麼；二是改名本身：實作者估套件裡約 400 處有「變更」兩個字、不全是 PR 的意思（例如「設定變更攔截」），施工時要逐處判斷；三是「通用」：哪天換到叫法不同的平台要再改一次字（範本只有 GitHub 一種，眼前不付）。
- 教訓：規矩的用字跟平台畫面、AI 對裁示者講話用同一個字；為了「通用」挑的抽象詞，讀規矩的人讀一遍不懂就換掉，換掉要付的代價照實寫出來；改名前先數出現幾處、哪些不是這個意思。
