# 假替身比真的寬鬆、間歇紅被當成負載和抖動，一道牆的收尾從第一天就沒生效

- 日期：2026-09-01
- 本文條號：E8、H1
- 發生什麼：讀上傳 PDF 時有一道「數到上限就取消讀取」的牆，08-02 隨 PFW #350 合併。取消的兩處呼叫都少帶一個參數；被呼叫的外部套件第一步就拒絕這種呼叫，拒絕又被一個空的錯誤處理吞掉，所以這道牆的收尾從合併起沒生效過。考題裡的假替身（＝考題裡假扮外部套件的假物件）取消時不收參數、不驗理由，收下了真套件會拒絕的呼叫，打在它上面的考題測的是一個不存在的世界。走真套件、真的撞到上限的三題，等的是這個錯造成的卡死撐到逾時：綠燈是為了錯的理由。更早在 08-01，「子行程安靜退出」被診斷成套件自己卡死，考題註解還寫著「綠燈是為了錯的理由」；這個誤診寫進了程式與兩份契約。08-27 到 09-01，雲端前瞻工作（＝用最新版執行環境跑、紅了不擋部署的那個工作）間歇紅。據實作者提案文件的轉述，擁有者 08-28 回報，當時的解釋是雲端負載重；案例簿另有兩則（相關的前兩則）把同一個紅記成主幹既有抖動。實作者從雲端日誌的錯誤輸出追到那個少帶的參數；修法 PR 說明寫，十場紅的錯誤輸出逐字相同。據實作者寫在程式註解的日期，根因 08-29 就追到；提案最早的提交是 08-30，修法 PR 到 09-01 才開出。09-01 另一個工作階段沒先看到這支（它自己的留言說的），開了 PFW #539 治症狀：讓子行程吞掉非同步例外；它自己的說明寫，這樣真的當掉也要等到逾時。開出約兩分鐘後，它讓道關掉。
- 代價：量到的：往前查到 08-17，第一次帶這句錯誤的紅是 08-27 19:57（UTC）主幹那一次。從那次到修法 PR 開出前，前瞻工作實際跑了的 171 次裡紅了 49 次；其中 48 次是同一句錯誤、都含同一個斷言失敗（13 次連同族另外兩題一起紅），主幹上占 7 次（修法 PR 說明寫「十場」，比量到的少）。另一支變更（PFW #535）在這個工作紅之後重跑了四次。修的那支第 1 到第 7 輪都要求修改，第 8 輪才第一次通過；掃描後回頭改，第 10 輪再通過，09-03 合併，整支改了 14 個檔。第 1 輪的複審就寫根因修法本身到位；照各輪留言與修法 PR 說明的處置表，多數退回打在修法新加的護欄、考題與註解上。影響範圍寫在提案文件，量到的和沒重現到的分開：卡死那條實作者在本機重現（真子行程給 120 秒，零輸出）；照設定，雲端遇到超標檔要等三十秒逾時，訊息把原因說錯。競速輸掉、子行程自己炸掉而回伺服器錯誤那條，本機試了三種時機都沒重現到，證據是雲端日誌。單機版那次讀取卡住不回（提案裡量到 40 秒沒回來）。有沒有真的使用者踩到，沒查；提案文件說真實帳單離上限很遠。
- 教訓：假替身要照抄真東西會拒絕什麼，比真的寬鬆就是在測不存在的世界；綠了也要問為什麼綠，靠逾時或卡死拿到的綠，可能正是錯本身；間歇紅的錯誤輸出每次逐字相同，先當成同一個真錯追，不先歸給負載；主幹也紅只排除「是這支弄的」，不等於抖動。
