# 機器負載把計時考題弄紅

- 日期：2026-09-02
- 本文條號：辛1、辛4、戊2
- 發生什麼：一天內八支以上變更同時在飛、十八個審查程序併行，機器負載飆到正常的好幾倍，量時間與量記憶體的考題間歇紅、單獨重跑全過；推送前守門與跨變更試合併閘都跑全卷，實作者被擋下、看起來像自己弄壞的。裁示者裁「等負載降」而不是授權跳過閘，之後兩支變更把那幾題改成量處理器工作量與因果上界。另一次推送前守門掛住六十三分鐘、日誌完全不動，實作者沒去看它有沒有在動就回報「機器忙、等它跑完」。
- 代價：多次推送與合併被擋、一次守門空等一小時；被裁示者要求等而非跳過。
- 教訓：被擋先看負載、再問「紅的是哪一題」、本支有沒有動那個檔、單獨重跑；環境紅不是跳過閘的理由；推送前守門要有時間上限並印出卡在哪一題。
