# ai-collab-kit

一套可以搬到任何專案的「一個人＋兩個以上 AI」協作架構。

## 目的（每一條規矩、每一道閘、每一題考題都以它為方針）

擁有者 2026-09-13 定的：**建立一個組織架構，讓他未來能夠順暢地調度 AI（軍隊），來實現他想製作的專案。**

換成可以拿來判斷的話：他是指揮官，AI 是部隊；架構的目的是**他下令、部隊可靠地做出來、他不必逐一盯**。「順暢」指的是**他的**摩擦最小——讀得少、裁得少、不用記程序。閘與考題的價值是讓他不必自己檢查就能信任結果，不是為了防誰使壞。可搬性是為了同一套編制能派到任何新專案。

所以一條規矩、一道閘、一題考題進來之前，多問一句：**這讓他調度更順、還是只是另一道疤？** 只因為過去某次事故而存在、但不讓調度更順的東西，是候選刪除對象。

從 personal-finance-webapp 兩個月、六百多支 PR 的經驗重建。**不是搬過來，是從零重寫**：一條規矩要進來，必須帶著它的理由和它的執行者。原專案的協作規矩四份加起來約 13 萬 5 千字（規則正本那一份約 9 萬 6 千字；這是**字元**數，不是位元組——本檔原本寫「19 萬字」是把位元組當字數，2026-09-13 量過改正），根本原因是規矩本文、事故沿革、邊界說明三種東西攪在同一份文件裡；這裡把它們分成三層。

## 三層

- `RULES.md`：**本文**（**產物，不要手改**：規矩住在 `rules.json`，一則一筆；改完跑 `node tools/build-rules.js` 重新產生。考題會比對兩者逐字元相同）。**規矩正文**上限 7,000 字（本文 K2）；哪些字算、哪些不算只寫在 `MACHINES.md` 的 K2 那一列（裁示者 2026-09-12 先定「一頁約三千字」、只數規矩本身；2026-09-25 放寬到四千、09-26 再放寬到七千）。只放背得起來、天天要用的規矩；新條要先過下面「進門規則」的進門五問。版面約定（條號、角色名、關鍵詞、灰底框怎麼排）與每個關鍵詞的意思在 `GLOSSARY.md`（用語對照表；不算字數，跟本文一起搬）。

  條號＝**英文字母＋數字**（`A1`、`B2`…）：字母是小節、數字是該節裡的第幾條。原本用天干（甲乙丙…）只有十個、不夠擴充，裁示者 2026-09-12 裁改成字母，A 到 Z 共二十六節。新增小節就往後接一個字母；小節內新增就接下一個數字。已經用掉的條號原則上不回收再指別條，案例簿與範本都靠條號指回來。第二輪（裁示者 2026-09-26 定案）是例外：舊 C1、C2 併成新 C1、舊 C3 遞補成 C2，舊 E9 拆成 E9、E10；同一支PR把指錯條號的案例一起改。案例簿考題擋得到「條號不存在」與「有條規矩沒案例指著」，擋不到「條號還在、意思換了」，那一半靠自覺。
- `cases/`：**案例簿**（索引 `cases/README.md` 是**產物**：由案例檔與 `cases/index.json` 算出來，改完跑 `node tools/build-casebook-index.js`）。每一條規矩為什麼存在：哪一次事故、哪一天、代價多少。一則一檔、檔名英文、每則指回本文的一條。⚠️ 進公開倉庫前要先去掉任何個人狀況。
- `settings.json` → `PROJECT-SETTINGS.md`：**專案設定**。值只有一份（`settings.json`），人讀的那份是產物；每個專案搬進去後逐欄填。套件倉庫根目錄那一份填的是**套件倉庫自己的值**（2026-09-26 起，讓合併指令在套件倉庫跑得起來）；給新專案的空白範本＝`tests/helpers/unfilled-settings.json`。
- `tools/`、`templates/`、`tests/`：**機器**。守得住的規矩寫成腳本、考題、範本。本文只寫「這條有機器守」，不重述機器做什麼。

## 搬進一個專案

照順序做；每一步後面寫的是「漏了會怎樣」。第一個真專案（personal-finance-webapp）2026-09-15 起在它的雲端三關全綠（`tests/placement.test.js` 檔頭有記）、2026-09-17 起它的協作規矩正本改為套件本文（它的 AGENTS.md 有記）；本倉庫 2026-09-26 起也用同一套管自己。步驟仍是修到哪補到哪。

1. 從套件的一個**固定版本**取檔（`git archive <版本> <路徑…>`，不要整個資料夾照抄）：`tools/`、`tests/`、`templates/`，加上根目錄的 `rules.json`、`RULES.md`、`MACHINES.md`（工具與考題從根目錄讀它們）、`GLOSSARY.md`（用語對照表：本文的版面約定與關鍵詞，本文檔頭指著它）、`docs/money-guard-two-pattern-tables.md`（禁區攔截器「兩張樣式表」的正本；`tests/forbidden-tools.test.js` 的 ⑭ 釘著它在不在——只搬這一個檔、不搬整個 docs/）；`settings.json` **不要從根目錄取**——套件倉庫根目錄那份是套件倉庫自己的值（平台、倉庫身分、參與者、合併指令都指向套件倉庫），要從空白範本取：`git show <版本>:tests/helpers/unfilled-settings.json > settings.json`，逐欄填完再跑 `node 2026-09-26／27：同一個連接器不用每個專案都填一遍、禁區不管哪個專案都要一樣）：碰錢連接器與白名單（所有碰錢連接器共用一份：唯讀查詢＋提醒／觀察清單＋回饋一支）、拒絕清單（兩支下單工具＋測試鈕）、不碰錢的連接器、家族網詞表、兩張樣式表，抄了就有；`tests/forbidden-defaults.test.js` 要求專案擋的方向那六個清單（`servers`、`deny`、`verbs`、`nouns`、兩張樣式表）至少包含它（少一項就紅；可以多加、不可以少）；放行方向那三個（`safeServers`、`allowlist`、`readPrefixes`）不比——專案可以自己拿掉＝更嚴（裁示者 2026-09-27）；任何一欄多加一項這一題都不比（放行三欄多加、`servers` 多登記一個連接器都可能更鬆），那是改禁區清單本身，照第 3 步的手續；同一支考題也釘住範本自己的筆數與正本「預設字彙表」的表格（範本縮水、正本改了範本沒跟上都紅）。⚠️ 連接器登記名是**這個 claude.ai 帳號**的連接器編號（桌面內建與 Codex 的用名字）——換帳號＝編號不同，把新帳號的編號**補進** `servers`／`safeServers`（碰錢那一欄的舊編號留著：考題要求至少包含範本，舊編號在新帳號永遠比不到、留著無害，要拿掉先改套件範本；不碰錢那一欄的舊編號可以拿掉；拒絕清單那兩支下單工具的名字也綁著舊編號，要照新編號補一份）（並照第 3 步重印釘指紋那一行、補複本、重按信任）；預設字彙表加了哪些字、刻意不加的字與代價、守不到的＝正本「兩張樣式表」那一份裡「預設字彙表」那一節。抄錯了會紅：`tests/settings.test.js` 有一題比對設定裡的倉庫身分跟這棵樹的 origin 遠端，指向別的倉庫就擋下；`cases/` 看專案要不要帶（它可能含私人紀錄，公開倉庫先想清楚），**帶不帶要登記**：`settings.json` 機器表「案例簿考題＋索引產生器」那一列，帶＝已啟用、不帶＝未移植（改完跑 `node tools/build-settings.js`）。登記跟 `cases/` 在不在對不上就紅（`tests/casebook.test.js`）；不帶的專案裡案例簿那四題顯示跳過並寫出原因。不帶案例簿的專案沒有「本文每一條都有案例指著」這道檢查，所以規矩本文預設在套件那邊改、再同步過去（用例外先在專案改的，要等搬回套件那一支才過案例簿檢查）。**不要帶** `README.md`、`package.json`、`package-lock.json`、`.gitignore`、`.node-version`、`.github/`——那幾份是專案自己的（`package-lock.json`、`.node-version`、`.github/` 是套件倉庫自己跑雲端檢查用的），覆蓋掉會弄壞專案。取完檔在專案根目錄跑 `node `mcp__`、不是工具名那一段；不碰錢那一欄的放行只認標準形狀 `mcp__<登記名>__<工具名>`（工具名非空、不以 `_` 開頭、裡面不含 `__`），名字多一層前綴、或連接器名本身含 `__` 時要把實際的連接器段整段登記（例如 `prefix__vendor`）；一個連接器一筆、逐字、沒有萬用字元（`ccd_session` 蓋不到 `ccd_session_mgmt`）；填 ## 本倉庫自己怎麼合併

這一節只寫套件倉庫自己的值（這份 README 不跟著搬進使用專案）；規矩本身照本文，這裡用條號指回、不複述。

- **誰**：實作者、複審者照「PR說明」的協作欄位；沒指定時照專案設定的預設分工（A1）。識別值與預設分工都在 `settings.json`（`PROJECT-SETTINGS.md` 第一節）。
- **雲端**：已開 PR 的分支每次更新跑兩個 job（主幹每次更新只跑三關；只改「PR說明」只重跑協作欄位；還沒開 PR 的分支推送不跑）——「三關」（`.github/workflows/ci.yml`，照 `settings.json` 的 checks 跑；套件零相依，三關只有 `node --test` 一關，沒有型別與風格兩關）與「協作欄位（實作者 ≠ 複審者）」（`.github/workflows/collab-fields.yml`）。兩個 job 名要在平台的分支保護設成必過檢查，名字逐字相同（E3、H3）。改 job 名的那一支：新名字的檢查在那一支最新版本上跑綠之後、合併之前，由擁有者把分支保護的必過檢查換成新名（來源維持 GitHub Actions）。沒換＝那一支永遠等不到舊名字、合不了；換了以後，還沒改名的其他開著的 PR 反過來等不到新名字（推論，沒在平台上實跑）。用傳統分支保護規則（classic branch protection rule）、不要用規則集（ruleset）：登記的 requiredChecks 指令只讀傳統規則那一組端點，規則集讀不到、真考卷閘會一直退 2（推論，沒實測規則集）；勾「對管理員一樣生效」（不勾＝對唯一的那個帳號無效）、審核人數 0（三方共用一個帳號，設 1 就永遠合不了）、不勾「要跟上最新主幹」。套件倉庫是私有的：雲端檢查用 Actions 分鐘數，草稿也跑、改說明也跑，兩份設定檔都沒有設時間上限（GitHub 對單一 job 的預設上限 360 分鐘＝推論，依官方文件）。
- **送審**：送審提示照 `templates/review-request.md`，實作者只填事實（F3）；模型、推理、不開的自動模式照 `PROJECT-SETTINGS.md` 第十一節（F11）。實作者先備兩份固定在受審版本的工作資料夾（樹），都放在系統暫存區：審查樹、突變副本（F1）；每輪審完由實作者收（`git worktree remove`；突變副本裡有改過的檔，要加 `--force`）。指令裡的模型名照第十一節填，換模型時只改那一節。

  ```bash
  git -C <本機套件倉庫> fetch
  git -C <本機套件倉庫> worktree add --detach <審查樹> <受審版本>
  git -C <本機套件倉庫> worktree add --detach <突變副本> <受審版本>
  ```

  Codex 當複審者（工作目錄＝審查樹；2026-10-03 #30 兩輪用過）。它的沙箱准寫審查樹與系統暫存區，所以突變副本放在暫存區就改得到；唯讀與不合併全靠提示（第十一節）。退出碼一律 0，跑完要自己去 PR 看結論留言在不在：

  ```bash
  codex exec -m <第十一節的最強模型> -c model_reasoning_effort='"<第十一節的最高推理>"' -s workspace-write -c sandbox_workspace_write.network_access=true -C <審查樹> - < <送審提示檔>
  ```

  Claude 當複審者（工作目錄＝審查樹；放行清單是 2026-10-03 在玩具資料夾實測的寫法換成本倉庫的考題指令，本倉庫沒實跑過，`gh pr comment` 那一條也沒測過）。兩個路徑都寫絕對路徑，`Edit(/<突變副本>/**)` 展開後開頭是兩條斜線，那是絕對路徑的寫法。帶 `--setting-sources user,project` 是為了不讀主目錄的本機設定檔（它會跟進工作資料夾）。助手被拒時最後的輸出看不到，要在輸出檔逐筆搜 `has been denied`：

- **複審結論**：由複審者自己貼成 PR 底下的一般留言（`gh pr comment`；不要用 `gh pr review`——結論聯集閘只讀 PR 的一般留言），第一行照 `templates/verdict-header.md` 逐字，來源字串照 `PROJECT-SETTINGS.md` 第二節（F4、F5）；「通過」那一則還要有兩個固定小標（F7）。
- **掃描**：套件倉庫沒有掃描者與隔離盒；每支在「### 複審後掃」下逐字寫「未執行：本專案無掃描者」（低風險的改寫「未執行：低風險，表定不掃」；G1），轉正式由實作者做（`settings.json` 的 scanner；G3、G4）。
- **合併**：由實作者跑合併指令（A4；按之前不用問裁示者，A5 列的三種情況除外）。在 HEAD 等於受審版本的工作資料夾（樹）根目錄（實作者自己的常設樹即可；不要在突變副本），先 `git fetch`（跨PR試合併那道閘要看得到其他開著的 PR 的版本），再跑 `node tools/merge.js <編號> --merger <實作者的識別值>`（H1）。先轉正式：`gh pr ready <編號> -R teacherjung/ai-collab-kit`（平台介面的 markReady 刻意封住，這一步手動做；G4）。退非零時先用 `gh pr view <編號> -R teacherjung/ai-collab-kit --json state` 看是不是其實已經合了，不要重跑：合併指令對任何非零都回 1，平台可能已經合了、後面那一步（例如刪遠端分支）才失敗。本倉庫的合併指令帶 `-R`，不碰本機分支：合併後本機分支與工作資料夾（樹）要自己清。合併後，合併的那一方把桌面主目錄更新到最新（擁有者 2026-10-03 選「A」：主目錄不會自己更新，曾一路落後 14 版沒人發現，在那裡工作的 AI 讀到舊規矩）：只在它乾淨時做、只往前追、不覆蓋任何東西——`git -C <桌面主目錄> status --porcelain` 沒有輸出，才跑 `git -C <桌面主目錄> pull --ff-only`；有輸出就停下來告訴擁有者。⚠️ 第 1 批（把 A4 改成實作者按的那一支）自己照合併當時主幹上的舊 A4 合：由審過它的那一方跑合併指令。
- **驗收**：套件倉庫沒有畫面與部署；改動在同步進使用專案的那一支，照該專案的驗收走。
