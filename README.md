# ai-collab-kit

一套可以搬到任何專案的「一個人＋兩個以上 AI」協作架構。

從 personal-finance-webapp 兩個月、六百多支 PR 的經驗重建。**不是搬過來，是從零重寫**：一條規矩要進來，必須帶著它的理由和它的執行者。原專案的協作規矩長到約 19 萬字，根本原因是規矩本文、事故沿革、邊界說明三種東西攪在同一份文件裡；這裡把它們分成三層。

## 三層

- `RULES.md`：**本文**。一頁。**規矩正文**上限 3,000 字——節標題、條號、句尾的執行者標籤不算（裁示者 2026-09-12 兩次裁示：先定「一頁約三千字」，再定只數規矩本身）。只放背得起來、天天要用的規矩。
- `cases/`：**案例簿**。每一條規矩為什麼存在：哪一次事故、哪一天、代價多少。一則一檔、檔名英文、每則指回本文的一條。⚠️ 進公開倉庫前要先去掉任何個人狀況。
- `tools/`、`templates/`、`tests/`：**機器**。守得住的規矩寫成腳本、考題、範本。本文只寫「這條有機器守」，不重述機器做什麼。

## 進門規則

一條規矩要進本文，三件都要有，缺一不進：

1. **理由**：案例簿裡有一則指著它。
2. **執行者**：哪支腳本或考題在守它；沒有就老實標「靠自覺」。
3. **通用**：不綁任何專案的檔名、人名、工具名。

本文的長度由 `tests/rules-length.test.js` 守；加條的取捨規矩只有一份，在本文 子2。標籤定義與每個機器的移植狀態在 `MACHINES.md`。

## 狀態

- 2026-09-12 開案。原料＝原專案協作規矩的逐條盤點（規矩族、執行者反證、記憶裡的事故表）。
- 草稿期不走 PR 審查；三個里程碑（本文初稿／案例簿初稿／機器搬完）各送 Codex 審一次；成形後用套件自己的流程管自己。里程碑 1（本文）2026-09-12 五輪通過，紀錄＝issue #1；里程碑 2（案例簿）送審中。
- 第一個使用者＝personal-finance-webapp：它的協作規矩已凍結，等這裡成形後整份換掉。
