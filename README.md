# ai-collab-kit

一套可以搬到任何專案的「一個人＋兩個以上 AI」協作架構。

## 目的（每一條規矩、每一道閘、每一題考題都以它為方針）

裁示者 2026-09-13 定的：**建立一個組織架構，讓他未來能夠順暢地調度 AI（軍隊），來實現他想製作的專案。**

換成可以拿來判斷的話：他是指揮官，AI 是部隊；架構的目的是**他下令、部隊可靠地做出來、他不必逐一盯**。「順暢」指的是**他的**摩擦最小——讀得少、裁得少、不用記程序。閘與考題的價值是讓他不必自己檢查就能信任結果，不是為了防誰使壞。可搬性是為了同一套編制能派到任何新專案。

所以一條規矩、一道閘、一題考題進來之前，多問一句：**這讓他調度更順、還是只是另一道疤？** 只因為過去某次事故而存在、但不讓調度更順的東西，是候選刪除對象。

從 personal-finance-webapp 兩個月、六百多支 PR 的經驗重建。**不是搬過來，是從零重寫**：一條規矩要進來，必須帶著它的理由和它的執行者。原專案的協作規矩四份加起來約 13 萬 5 千字（規則正本那一份約 9 萬 6 千字；這是**字元**數，不是位元組——本檔原本寫「19 萬字」是把位元組當字數，2026-09-13 量過改正），根本原因是規矩本文、事故沿革、邊界說明三種東西攪在同一份文件裡；這裡把它們分成三層。

## 三層

- `RULES.md`：**本文**（**產物，不要手改**：規矩住在 `rules.json`，一則一筆；改完跑 `node tools/build-rules.js` 重新產生。考題會比對兩者逐字元相同）。一頁。**規矩正文**上限 3,000 字——節標題、條號、句尾的執行者標籤不算（裁示者 2026-09-12 兩次裁示：先定「一頁約三千字」，再定只數規矩本身）。只放背得起來、天天要用的規矩。

  條號＝**英文字母＋數字**（`A1`、`B2`…）：字母是小節、數字是該節裡的第幾條。原本用天干（甲乙丙…）只有十個、不夠擴充，裁示者 2026-09-12 裁改成字母，A 到 Z 共二十六節。新增小節就往後接一個字母；小節內新增就接下一個數字。已經用掉的條號不要回收再指別條，案例簿與範本都靠條號指回來。
- `cases/`：**案例簿**（索引 `cases/README.md` 是**產物**：由案例檔與 `cases/index.json` 算出來，改完跑 `node tools/build-casebook-index.js`）。每一條規矩為什麼存在：哪一次事故、哪一天、代價多少。一則一檔、檔名英文、每則指回本文的一條。⚠️ 進公開倉庫前要先去掉任何個人狀況。
- `settings.json` → `PROJECT-SETTINGS.md`：**專案設定**。值只有一份（`settings.json`），人讀的那份是產物；每個專案搬進去後逐欄填。
- `tools/`、`templates/`、`tests/`：**機器**。守得住的規矩寫成腳本、考題、範本。本文只寫「這條有機器守」，不重述機器做什麼。

## 搬進一個專案

照順序做；每一步後面寫的是「漏了會怎樣」。還沒對真專案組裝到三關全綠過，其餘步驟修到哪補到哪。

1. 從套件的一個**固定版本**取檔（`git archive <版本> <路徑…>`，不要整個資料夾照抄）：`tools/`、`tests/`、`templates/`，加上根目錄的 `settings.json`、`rules.json`、`RULES.md`、`MACHINES.md`、`PROJECT-SETTINGS.md`（工具與考題從根目錄讀它們）；`cases/` 看專案要不要帶（它可能含私人紀錄，公開倉庫先想清楚），**帶不帶要登記**：`settings.json` 機器表「案例簿考題＋索引產生器」那一列，帶＝已啟用、不帶＝未移植（改完跑 `node tools/build-settings.js`）。登記跟 `cases/` 在不在對不上就紅（`tests/casebook.test.js`）；不帶的專案裡案例簿那四題顯示跳過並寫出原因。不帶案例簿的專案沒有「本文每一條都有案例指著」這道檢查，所以規矩本文在套件那邊改、再同步過去。**不要帶** `README.md`、`package.json`、`.gitignore`——那三份是專案自己的，覆蓋掉會弄壞專案。記下取的是哪一個版本，以後同步照同一份清單重取——**但 `settings.json` 與它產生的 `PROJECT-SETTINGS.md` 是專案自己填的值，同步時不要蓋掉**（套件的設定欄位有增減時，照新版把欄位補進專案那份——例如 2026-09-19 起 checks 多了 `mainWorktree`、`indexAnchors` 兩欄，沒補＝設定考題紅，補成「未設定」＝跟以前一樣不驗；蓋掉的話案例簿那一列會變回已啟用，錯誤訊息會提醒你改回未移植、不要把 `cases/` 複製進來）。**連 `tools/package.json`、`tests/package.json` 一起搬**。這兩份宣告「底下是 CommonJS」。專案根目錄若宣告 `"type":"module"`，少了它們每支工具第一行就崩——禁區攔截器崩掉＝兩家 AI 照常呼叫工具，錢的邊界靜靜失守（`tests/placement.test.js`）。
2. 專案若有 ESLint、而且把 `.js` 當 ES 模組：在它的設定補一組（package.json 的宣告管不到 lint）。漏了＝lint 對套件檔報幾百個錯，推送前那道門推不上去。

   ```js
   { files: ['tools/**/*.js', 'tests/**/*.js'], languageOptions: { sourceType: 'commonjs', globals: globals.node } }
   ```

3. 接禁區攔截器（B1），兩家 AI 各接一次。Claude 側二擇一。活讀裝法＝把 `templates/hook-claude.json` 那一組 PreToolUse **加到**專案 `.claude/settings.json` 既有清單的**尾端**，不是整份覆蓋；範本的說明鍵不要抄；`permissions.deny` 不要照範本清空，專案原有的逐字拒絕要留著。範本的指令跟 Codex 專案層同一招——先清 `GIT_` 那一族、再問版本控制的根目錄——因為平台給的專案目錄變數跟著「從哪個目錄開 Claude」走（2026-09-16 實測從子目錄開就指到子目錄），不能拿來找攔截器。釘指紋裝法＝**不要手填範本**（`templates/hook-claude-pinned.json`）。活讀那一行每次呼叫都讀當下那棵樹的清單——在樹裡把清單改弱、或切到弱清單的分支，下一次呼叫就照弱的判；釘指紋那一行只寫指紋、不含任何機器路徑，判斷一律讀倉庫外、內容定址的固定複本 `~/.local/share/ai-collab-kit/guard/<指紋>`：樹裡的清單怎麼改都沒有用；這台機器沒有那一行要的那一份複本、或複本裡多了東西＝所有 mcp__ 工具全擋（看得見）。順序（`tools/guard-copy.js` 檔頭是同一份，專案裡看得到；⓪同下——清單上要先有測試鈕）：①先補複本——`git fetch`，在專案裡跑 `node tools/guard-copy.js --claude`（不給 `--from`＝抽 `origin/<主幹>`）。它從已合併的版本抽那四個檔，先用你的家目錄跑一次 `/bin/sh -lc ':'`（標準輸出不是空的就不落地、退 1），再寫進暫存骨架、用 `/bin/sh -c` 與 `-lc` 真的各跑一遍那一行（無害假名放行、照清單該擋的假名印出拒絕、改過一個位元組的副本退 2），過了才落地；落地之後再用你的家目錄（會讀你的登入設定）跑一次，沒過就撤掉這一次落地的那一份、退 1——Claude 起鉤子是不是登入 shell 沒量，登入設定往標準輸出印字會把拒絕弄成放行。落地之後、這一次試跑跑完之前把它中斷＝那一份留著，下一次再跑走「已經在」那條路：試跑過＝退 0；沒過＝退 1、不撤它（訊息會說怎麼退掉）。這時接線還沒換，沒過就停在這裡、沒有全擋的空窗。不要用檔案管理程式打開複本目錄：它可能在裡面放東西（例如 `.DS_Store`；沒量），放了＝那一行全擋（看得見）；補救＝看過之後把那個目錄整個移走（`mv`）再跑 `--claude`（`--retire` 不收多了東西的目錄）。②跑 `node tools/guard-copy.js --claude-line`（只印、不寫檔、讀的是工作樹），把印出的兩組放進專案的 `.claude/settings.json`：PreToolUse 那一組換掉活讀那一組，ConfigChange 那一組（設定變更攔截）原樣放，`permissions.deny` 不動；走一支變更、審查、合併，不要手改那一行。③合併後：更新→關掉所有 Claude 對話重開→按測試鈕，看到拒絕理由含「在拒絕清單上」才算數；看到的是「…（指紋對不上）」那一句＝這台機器沒有那一行要的那一份，再跑一次 `--claude`、再按。④之後每次改到那四個檔（`settings.json` 的 forbidden 那一塊、`tools/forbidden-tools.js`、`tools/settings-data.js`、`tools/package.json`）：同一支變更重跑 `--claude-line` 換掉那兩組（沒換＝那一行照舊指紋找到舊複本、靜靜照舊清單判，收緊不生效；唯一會紅的是 `tests/claude-pin.test.js` 的等式題）→合併→每台機器更新、重開對話、按測試鈕——**這一下應該先看到「…（指紋對不上）」、沒有 pong**：複本還沒補；補複本刻意不自動（裁示者 2026-09-18），這一下等於順便重量一次「複本不在＝全擋」還有沒有效→`git fetch`、跑 `--claude`→再按一次，看到「在拒絕清單上」。收緊清單時多一步：舊的那一份用 `node tools/guard-copy.js --retire <舊指紋>` 退役（只刪名字是 64 碼、內容自洽的目錄，碰不到 Codex 全域層那種短名字的複本）。要知道的限制（只寫量到的；2026-09-18、Claude Code 2.1.275 桌面版）：對話中往專案 `.claude/settings.json` 多加一條鉤子同回合就生效，所以釘住的是清單與判斷程式（照倉庫外那一份判）、不是設定檔那一行；範本因此另帶一組設定變更攔截，它只量了專案設定檔這一個來源、量的時候是對話中途裝上的——那個對話裡的 AI 沒有收到任何提示文字（官方文件也寫這個事件擋下時不顯示訊息；使用者畫面那一場沒記），所以那一條只有 `exit 2`、磁碟上的檔照樣改得進去只是那個對話不載入（合法的設定改動也要重開對話才載入）、裝它的那一次改動本身不會被它擋、本機設定檔與使用者層沒量；它在平台上擋不擋，裝上時的驗收要再量一次（套件沒有寫怎麼量；照這裡的驗收步驟做量不到它），之後沒有例行動作重量它（測試鈕只走 PreToolUse 那一行）；鉤子的環境被塞變數（SHELLOPTS、匯入的 shell 函式、PATH）這一類擋不住，那一行裡關不完，設定變更攔截那一條一樣擋不住（SHELLOPTS=noexec＝退 0）——這一類在場時，這裡說的「退 2」「全擋」都不成立；那一條只有 `exit 2`、匯入的函式換不掉它，只在 /bin/sh（POSIX 模式；2026-09-18 量到鉤子的 $0 是 /bin/sh）下成立，官方鉤子文件寫 shell 欄位預設「bash」，這個落差守不到（MACHINES.md B1）；複本誰都造得出自洽的一份，它不是鎖；落後的樹與開著的舊對話照舊清單判、收緊變慢；指紋不蓋 node。使用專案要自己加一題釘「一定是釘指紋那一組」（`tools/claude-pin.js` 的 `claudePinStatus` 要回 `ok`）——套件的等式題遇到活讀裝法只是跳過並寫明。專案原本已經有一層攔截時，先讓兩層並存、確認新的那層真的在擋，再拆舊的——任何時刻都要至少一層在擋。**四種裝法（Claude 側活讀、Claude 側釘指紋、Codex 專案層、Codex 全域層）的驗收都一樣**（例外：Claude 側釘指紋那一次只驗到 PreToolUse 那一行，設定變更攔截那一組量不到）：叫禁區清單上刻意放的無害測試工具（條件見下面⓪），看到新那一層的拒絕理由（含「在拒絕清單上」）才算數；拆掉舊的那一層之後再做一次。任何會動到禁區的真工具，不論在不在清單上、不論攔截器擋不擋得住，一律絕不可以叫來試；驗收只准用清單上刻意放的無害測試工具，沒有就停下來先加。Codex 側二擇一：專案層＝`templates/hook-codex.json` 放進專案的 `.codex/hooks.json`；全域層＝**不要手填範本**，先 `git fetch`，在專案裡跑 `node tools/guard-copy.js --from <已合併進主幹的版本> --to <絕對路徑的新空目錄>`。目的地要在任何倉庫、暫存區、家目錄的 `.codex`／`.claude`（大小寫不同也算）以外，建議一個版本一個目錄，例如 `~/.local/share/ai-collab-kit/guard/<版本碼前幾碼>`。它只接受已經在 `origin/<主幹>` 裡的版本，從那個版本（不是工作樹）抽出攔截器會讀到的四個檔（設定只帶禁區清單那一塊）與接線範本，算出指紋，用 `/bin/sh -lc` 真的跑三次（無害假名要放行、照清單該擋的假名要退 2、改過一個位元組的副本要退 2），印出換好複本路徑與指紋的那一組。清單只靠樣式規則時，工具想不出該擋的假名，要加 `--deny-probe <照清單該擋的假工具名>`（只當字串餵給攔截器）。退 2＝拒絕、什麼都沒寫；退 1＝寫了但沒成功、沒有東西可以貼，目的地留下的東西看完自己刪（檔案是唯讀的，先 `chmod -R u+w`）。Codex 的信任只記那一行指令、不記複本，所以指令先自己核對：複本被改一個位元組、少檔、搬走、佔位沒換、裡面有任何連結或查不了有沒有連結（連結會讓指紋算的檔跟 node 讀的檔不是同一份；node 另外也不順著連結找檔）＝退 2、所有 mcp__ 工具都擋（看得見）；攔截器說拒絕時也退 2（登入設定往標準輸出印字會弄壞拒絕形狀，退 2 不受影響；同樣以鉤子的環境沒被塞 SHELLOPTS 之類的變數為前提）。**裝與換只有一條順序**（`tools/guard-copy.js` 檔頭是同一份，專案裡看得到）：⓪先確認禁區清單（settings.json 的 forbidden.deny）裡有一個刻意放的無害測試工具：它要是 Codex 連得到的伺服器上真的存在的 mcp__ 工具，就算真的執行了也不會動到禁區、不會造成任何改變，而且不可以是禁區連接器（forbidden.servers）上的任何工具——連唯讀的查詢也不行；原本還有別的攔截組並存時，挑一個只有這份清單擋、別組不擋的名字。套件帶了一支現成的＝`tools/canary-server.js`（掛上去只回一句 pong，什麼都不做），工具名 `mcp__guard_canary__ping`，兩家 AI 各登記一次的做法見 `templates/canary-install.md`。清單上還沒有就先加、合併，再從①開始——沒有就停下來，不可以拿任何別的工具代替。①先 git fetch，在專案裡跑 node tools/guard-copy.js --from <已合併進主幹的版本> --to <新的空目錄>（建議家目錄底下固定的地方，例如 ~/.local/share/ai-collab-kit/guard/<版本碼前幾碼>）。②關掉所有 Codex 視窗（改鉤子檔到按下信任之間，改過的那一組是停用的：Codex 對沒信任的鉤子一聲不吭地跳過，這段時間不能有 Codex 在跑）。③編輯家目錄 .codex/hooks.json：第一次裝＝把印出的那一組加到 hooks.PreToolUse 最後面（原本有別的攔截組就讓它們並存）；換新複本＝在原位置換掉舊複本那一組。④開 Codex、按信任。⑤在 Codex 叫⓪那個無害測試工具：要看到被擋，而且擋的理由是這一組的（理由含「在拒絕清單上」；「固定複本不在、被改過…（指紋對不上）」那一句不算，那是複本壞了）。叫一般工具照常能用證明不了什麼（鉤子沒跑時它也能用）。⑥⑤沒看到這一組的拒絕＝關掉 Codex、把原來那一組放回去（換新複本時舊複本目錄還在）、按信任，再查原因；⑤過了、而且是換新複本，這時才刪舊的複本目錄（先 chmod -R u+w；先刪會讓舊那一組把所有 mcp__ 工具全擋）。之後要拆掉並存的別的攔截組：同樣先關 Codex、刪那一組、對剩下的按信任（位置變了），再做一次⑤。要重抽的時候＝settings.json 的 forbidden
