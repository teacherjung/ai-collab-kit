# ai-collab-kit

一套可以搬到任何專案的「一個人＋兩個以上 AI」協作架構。

## 目的（每一條規矩、每一道閘、每一題考題都以它為方針）

裁示者 2026-09-13 定的：**建立一個組織架構，讓他未來能夠順暢地調度 AI（軍隊），來實現他想製作的專案。**

換成可以拿來判斷的話：他是指揮官，AI 是部隊；架構的目的是**他下令、部隊可靠地做出來、他不必逐一盯**。「順暢」指的是**他的**摩擦最小——讀得少、裁得少、不用記程序。閘與考題的價值是讓他不必自己檢查就能信任結果，不是為了防誰使壞。可搬性是為了同一套編制能派到任何新專案。

所以一條規矩、一道閘、一題考題進來之前，多問一句：**這讓他調度更順、還是只是另一道疤？** 只因為過去某次事故而存在、但不讓調度更順的東西，是候選刪除對象。

從 personal-finance-webapp 兩個月、六百多支 PR 的經驗重建。**不是搬過來，是從零重寫**：一條規矩要進來，必須帶著它的理由和它的執行者。原專案的協作規矩四份加起來約 13 萬 5 千字（規則正本那一份約 9 萬 6 千字；這是**字元**數，不是位元組——本檔原本寫「19 萬字」是把位元組當字數，2026-09-13 量過改正），根本原因是規矩本文、事故沿革、邊界說明三種東西攪在同一份文件裡；這裡把它們分成三層。

## 三層

- `RULES.md`：**本文**（**產物，不要手改**：規矩住在 `rules.json`，一則一筆；改完跑 `node tools/build-rules.js` 重新產生。考題會比對兩者逐字元相同）。一頁。**規矩正文**上限 3,000 字——節標題、條號、句尾的執行者標籤不算（裁示者 2026-09-12 兩次裁示：先定「一頁約三千字」，再定只數規矩本身）。只放背得起來、天天要用的規矩。

  條號＝**英文字母＋數字**（`A1`、`B2`…）：字母是小節、數字是該節裡的第幾條。原本用天干（甲乙丙…）只有十個、不夠擴充，裁示者 2026-09-12 裁改成字母，A 到 Z 共二十六節。新增小節就往後接一個字母；小節內新增就接下一個數字。已經用掉的條號不要回收再指別條，案例簿與範本都靠條號指回來。
- `cases/`：**案例簿**（索引 `cases/README.md` 是**產物**：由案例檔與 `cases/index.json` 算出來，改完跑 `node tools/build-casebook-index.js`）。每一條規矩為什麼存在：哪一次事故、哪一天、代價多少。一則一檔、檔名英文、每則指回本文的一條。⚠️ 進公開倉庫前要先去掉任何個人狀況。
- `settings.json` → `PROJECT-SETTINGS.md`：**專案設定**。值只有一份（`settings.json`），人讀的那份是產物；每個專案搬進去後逐欄填。
- `tools/`、`templates/`、`tests/`：**機器**。守得住的規矩寫成腳本、考題、範本。本文只寫「這條有機器守」，不重述機器做什麼。

## 搬進一個專案

照順序做；每一步後面寫的是「漏了會怎樣」。還沒對真專案組裝到三關全綠過，其餘步驟修到哪補到哪。

1. `tools/`、`tests/`、`templates/` 放在專案根目錄，**連 `tools/package.json`、`tests/package.json` 一起搬**。這兩份宣告「底下是 CommonJS」。專案根目錄若宣告 `"type":"module"`，少了它們每支工具第一行就崩——禁區攔截器崩掉＝兩家 AI 照常呼叫工具，錢的邊界靜靜失守（`tests/placement.test.js`）。
2. 專案若有 ESLint、而且把 `.js` 當 ES 模組：在它的設定補一組（package.json 的宣告管不到 lint）。漏了＝lint 對套件檔報幾百個錯，推送前那道門推不上去。

   ```js
   { files: ['tools/**/*.js', 'tests/**/*.js'], languageOptions: { sourceType: 'commonjs', globals: globals.node } }
   ```

## 進門規則

一條規矩要進本文，三件都要有，缺一不進：

1. **理由**：案例簿裡有一則指著它。
2. **執行者**：哪支腳本或考題在守它；沒有就老實標「靠自覺」。
3. **通用**：不綁任何專案的檔名、人名、工具名。
4. **服務目的**：說得出它讓裁示者調度 AI 哪裡更順（少讀、少裁、少記、或不必自己檢查）；說不出來就算有案例也不進。

本文的長度由 `tests/rules-length.test.js` 守；加條的取捨規矩只有一份，在本文 K2。標籤定義與每個機器的移植狀態在 `MACHINES.md`。
